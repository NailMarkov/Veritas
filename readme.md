# Parsing of failed operations Automation System

Автоматизированная система мониторинга, парсинга и архивации текстовых логов на базе PowerShell.

## 🛠 Структура проекта

Проект организован по модульному принципу. Все пути и имена папок соответствуют лучшим практикам автоматизации (латиница, PascalCase/kebab-case, отсутствие пробелов).

```text
LogProcessing/
├── logs_files/               # Входная папка для новых (необработанных) логов
├── processed_logs/           # Временная папка для успешно обработанных логов
├── results/                  # Конечные результаты проверки и парсинга
│   └── 2026-08-07_124500/    # Динамические папки отчетов (ГГГГ-ММ-ДД_ЧЧММСС)
│       ├── summary-report.csv
│       └── error-details.log
├── Watch-LogsDirectory.ps1   # Главный скрипт-монитор (Диспетчер)
├── Parse-LogContent.ps1      # Скрипт-парсер (Бизнес-логика)
└── README.md                 # Документация проекта
|____

```

## ⚙️ Как работает приложение

Процесс обработки состоит из 4 последовательных этапов:

### Этап 1: Мониторинг (`Watch-LogsDirectory.ps1`)
* Скрипт-диспетчер проверяет входную директорию `logs_files`.
* Если папка пуста, скрипт завершает работу (или засыпает, если настроен цикл).
* Если обнаружены новые файлы логов, диспетчер переходит к следующему шагу.

### Этап 2: Парсинг и обработка (`Parse-LogContent.ps1`)
* Главный скрипт передает управление специализированному скрипту парсинга.
* `Parse-LogContent.ps1` считывает содержимое логов, фильтрует ошибки, собирает метрики и статистику.

### Этап 3: Генерация отчетов
* Внутри директории `results/` автоматически создается новая подпапка. 
* Имя подпапки генерируется динамически по маске даты и времени (например, `results/2026-08-07_124500/`), чтобы избежать перезаписи отчетов.
* В эту подпапку сохраняются структурированные файлы с результатами (например, `.csv` отчеты или `.log` выжимки).

### Этап 4: Ротация и подготовка к архивации
* После успешного парсинга исходные файлы логов атомарно перемещаются из папки `logs_files/` в папку `processed_logs/`.
* Это гарантирует, что логи не будут обработаны повторно при следующем запуске системы, и подготавливает их к перемещению в долгосрочный архив (нажмите [сюда](#), если требуется настроить `Move-ToArchive.ps1`).

## 🚀 Запуск и требования

1. Разверните структуру папок локально.
2. Поместите файлы логов для теста в папку `logs_files/`.
3. Откройте PowerShell и запустите главный диспетчер:

```powershell
.\Watch-LogsDirectory.ps1
```

*Примечание: Перед запуском убедитесь, что в вашей системе разрешено выполнение скриптов (`Set-ExecutionPolicy RemoteSigned -Scope Process`).*
